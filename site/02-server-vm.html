Guided exercise 2 server-create

Create the server VM

Create the RHEL 9 machine that will run Edge Manager. It starts from Red Hat's ready-made KVM guest image, so there is no installer to go through.

Outcomes

  • A VM rhem at 192.168.160.10 (rhem.lab.internal): 4 vCPUs, 6 GiB RAM, 80 GB disk.
  • You can log in with ssh -F ~/edgelab/ssh_config rhem as user cloud-user, with sudo.

Note

Sizing. Red Hat's stated minimum for Edge Manager is 4 vCPUs, 4 GB RAM and 70 GB disk for up to 100 devices. This VM gets 6 GiB because it also runs the registry and builds your device images: the largest step in this lab, building the device disk image, peaked at 4.6 GiB in use. The sizes in this lab are chosen so that all four VMs fit on a laptop with 16 GB of memory.

Before you begin

On the workstation, in ~/edgelab, confirm that the earlier exercises are complete:

./lab start server-create

Instructions

Make the disk

cp --sparse=always inputs/rhel-9.8-x86_64-kvm.qcow2 images/rhem.qcow2
qemu-img resize images/rhem.qcow2 80G
qemu-img info images/rhem.qcow2

image: images/rhem.qcow2
file format: qcow2
virtual size: 80 GiB (85899345920 bytes)
disk size: 1.28 GiB
...output omitted...
  • The guest image is a complete, minimal RHEL install in a 10 GB disk. You copy it, so the original stays untouched.
  • resize only raises the size the VM will see. The file grows as data is written, which is why it still uses about 1.3 GB.

Create the VM

virt-install is the standard tool for creating a libvirt VM from the command line. One command defines the VM and starts it:

virt-install --connect qemu:///system --name rhem --memory 6144 --vcpus 4 \
  --import --disk images/rhem.qcow2 --osinfo rhel9-unknown \
  --network network=rhem-lab,mac=52:54:00:a0:00:10 \
  --cloud-init clouduser-ssh-key=keys/id_ed25519.pub \
  --boot uefi --graphics none --noautoconsole

Starting install...
Allocating 'virtinst-…-cloudinit.iso'
Transferring 'virtinst-…-cloudinit.iso'
Creating domain...

Domain is still running. Installation may be in progress.
OptionMeaningEffect on the lab
--name rhem --memory 6144 --vcpus 4The VM's name in libvirt, its RAM in MiB, and its CPU count.Every later virsh command refers to it as rhem.
--import --disk images/rhem.qcow2Boot the existing disk as it is, instead of running an installer.The disk you just made becomes the server.
--osinfo rhel9-unknownTells libvirt this is a RHEL 9 guest, so it picks suitable virtual hardware (virtio disk and network)."unknown" means "RHEL 9, any minor release"; older tool versions do not know 9.8 by name.
--network network=rhem-lab,mac=…:10Connect to the lab network with this exact MAC address.The address is the one network.xml ties to the name rhem and to 192.168.160.10. That is how the VM gets its identity on the network.
--cloud-init clouduser-ssh-key=keys/id_ed25519.pubThe guest image has no users you can log in as. On first boot, cloud-init inside it reads settings from a small extra disk, which virt-install builds for you from this option.Your lab public key is installed for the image's built-in user, cloud-user, who has passwordless sudo. cloud-init also grows the filesystem to fill the 80 GB disk. No password logins exist.
--boot uefiUEFI firmware, with Secure Boot.The same firmware type the edge devices use later.
--graphics none --noautoconsoleNo graphical display, and do not attach your terminal to the VM's console.The command returns immediately and the VM boots in the background.

The message about an installation in progress is virt-install's standard wording; nothing is being installed. To watch the VM boot, use virsh -c qemu:///system console rhem (leave with Ctrl+]).

Log in

First boot takes about 30 seconds. Then:

ssh -F ~/edgelab/ssh_config rhem

You are now inside the server, as cloud-user. Check what you got:

cat /etc/redhat-release
hostname -f
df -h /

free -g

  • If ssh says "connection refused" or times out, the VM is still booting; try again.
  • The name rhem.lab.internal was not set inside the VM. The lab network handed it out along with the address. Edge Manager is told this name explicitly in the next module.

Leave the VM with exit for the next step.

Restart it once

virsh -c qemu:///system shutdown rhem
virsh -c qemu:///system domstate rhem

Repeat the second command until it prints shut off (a few seconds). Then:

virsh -c qemu:///system start rhem
virsh -c qemu:///system domstate rhem

Domain 'rhem' started

running

Note

Why restart a VM that works? virt-install treats the first boot as an installation: the cloud-init disk is attached only for that boot, and the first time the VM restarts it powers off instead, so the disk can be removed. Doing that now, on purpose, means a later reboot behaves normally instead of leaving your server switched off. After this, the VM's definition is final.

Evaluation

On the workstation, in ~/edgelab, grade your work. Every line should end in SUCCESS; a FAIL line is followed by what to do about it.

./lab grade server-create

You can also check by hand:

  • hostname -f prints rhem.lab.internal.
  • The root filesystem is about 79 GB.
  • sudo -n true && echo ok prints ok.

Keep this terminal open: it is your rhem VM terminal for the next modules.

Finish

./lab finish server-create
