Guided exercise 11 lab-teardown

Remove the lab

Remove everything the lab created, in the reverse order it was built. Afterwards the workstation is as it was before module 0, apart from the packages installed there.

Outcomes

  • The server's Red Hat registration is released.
  • The four VMs, the lab network and the ~/edgelab folder are gone.

Instructions

Release the Red Hat registration

The server VM is registered with your Red Hat account. Unregister it before deleting it, or it stays in your inventory as a system that no longer exists.

sudo subscription-manager unregister

Note

The edge devices are not registered; only the build ran with the server's entitlement.

Delete the VMs

virsh -c qemu:///system destroy edge-1
virsh -c qemu:///system destroy edge-2
virsh -c qemu:///system destroy edge-3
virsh -c qemu:///system destroy rhem
virsh -c qemu:///system undefine edge-1 --nvram
virsh -c qemu:///system undefine edge-2 --nvram
virsh -c qemu:///system undefine edge-3 --nvram
virsh -c qemu:///system undefine rhem --nvram
virsh -c qemu:///system list --all
  • destroy is libvirt's word for "power off now". It does not delete anything.
  • undefine --nvram removes the VM's definition and its UEFI settings file. The disk files in ~/edgelab/images are left for the last step.

Both commands were run while writing this guide.

Delete the network

virsh -c qemu:///system net-destroy rhem-lab
virsh -c qemu:///system net-undefine rhem-lab
virsh -c qemu:///system net-list --all

This also removes the bridge virbr-rhem, and with it the name lookup you set up for the web UI in module 4.

Grade the teardown

Do this before deleting the working folder, because the lab command lives in it:

./lab grade lab-teardown

The four VMs and the network must be reported as removed.

Delete the working folder

This deletes the VM disks, the lab SSH key, the clone of the guide, and your copies of (or links to) the three input files. If you saved the inputs here as files rather than links and want to keep them, move them out first.

make -C ~/edgelab/guide stop
cd ~
rm -rf ~/edgelab

The first line stops the guide's web server, if you started it.

Verification

virsh -c qemu:///system list --all
ls ~/edgelab

No lab VM is listed, and the folder no longer exists.

Where to go next

Topics this lab did not cover, and that have not been tested for this guide:

TopicWhy it follows from what you built
Backup and restoreYou saw that the CA, the database and the configuration are the server. Edge Manager has flightctl-backup and flightctl-restore for exactly that set.
Delta updatesNew in 1.4: devices download only the difference between their current image and the new one. Your devices already report deltaEligible: true.
Automatic rollbackHealth checks after an OS update (greenboot), so a device returns to the previous image by itself when the new one is unhealthy.
Private repositories and signed imagesThis lab made the registry public on the lab network. Pull secrets on devices and image signature verification close that gap.
Fleets from gitEdge Manager can read fleet definitions from a git repository, so a merged change becomes a rollout.
MicroShiftRed Hat Device Edge also includes MicroShift. A device image that contains it can run Helm applications from the same fleet.
