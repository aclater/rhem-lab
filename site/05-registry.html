Guided exercise 5 registry-install

Install a registry

Devices get their operating system and their applications as container images. Those images have to live somewhere the devices can reach. Here that is a registry on the server VM.

Outcomes

  • Red Hat's mirror registry (a small Quay) running on rhem at rhem.lab.internal:8443.
  • The server VM trusts the registry's certificate and is logged in to push.
  • Anyone on the lab network can pull what you push, without a login.

Note

Why your own registry? Edge Manager never sends images to devices. It only tells a device which image to run; the device pulls it. So the registry must be reachable from the edge, and it is as much a part of the deployment as the server. Putting it next to the server means one machine carries everything a device needs.

Before you begin

On the workstation, in ~/edgelab, confirm that the earlier exercises are complete:

./lab start registry-install

Instructions

Download the mirror registry

mkdir ~/mirror-registry
cd ~/mirror-registry
curl -LO https://mirror.openshift.com/pub/openshift-v4/x86_64/clients/mirror-registry/1.3.11/mirror-registry.tar.gz
curl -sL https://mirror.openshift.com/pub/openshift-v4/x86_64/clients/mirror-registry/1.3.11/sha256sum.txt | sha256sum -c --ignore-missing
tar xzf mirror-registry.tar.gz
ls

mirror-registry.tar.gz: OK
execution-environment.tar  image-archive.tar  mirror-registry  mirror-registry.tar.gz

About 730 MB. The archive carries the installer and the container images it needs, so the install itself downloads nothing.

Note

What it is. "Mirror registry for Red Hat OpenShift" is a single-machine build of Quay that Red Hat ships for disconnected installs. It is used here as a general-purpose registry for the lab's own images. Any registry that speaks the standard protocol over TLS would do; this one is Red Hat's and installs with one command.

Install it

The registry has its own administrator account, separate from the Edge Manager admin you created in module 4. Install the registry and give that account the lab password:

sudo ./mirror-registry install --quayHostname rhem.lab.internal:8443 --quayRoot /opt/quay --initUser admin --initPassword edgelab123

It runs for about two minutes and ends with:

Quay installed successfully, config data is stored in /opt/quay
Quay is available at https://rhem.lab.internal:8443 with credentials (admin, …)
OptionEffect
--quayHostname rhem.lab.internal:8443The name and port in the registry's certificate, and therefore in every image reference from now on. Edge Manager already uses 443, so the registry takes 8443.
--initUser admin --initPassword edgelab123The registry's first account and its password.
--quayRoot /opt/quayWhere its configuration and its own certificate authority are written.
sudoInstalls it as system services (quay-app, quay-postgres, quay-redis), which start at boot like Edge Manager's.
systemctl list-units "quay*" --no-pager --plain --no-legend

Let devices pull without a login

By default, a repository created by pushing an image is private. Change that default, so what you push is readable by anyone who can reach the registry:

echo "CREATE_PRIVATE_REPO_ON_PUSH: false" | sudo tee -a /opt/quay/quay-config/config.yaml
sudo systemctl restart quay-app

Note

The trade-off. With public repositories, a device needs only to trust the registry, not to hold a password for it. That keeps secrets out of the device image. It is right for this lab, where the registry is only reachable on the lab network. For private repositories, Edge Manager's documentation has you place a pull secret on the device: /etc/ostree/auth.json for OS images and /root/.config/containers/auth.json for application images.

Trust the registry and log in

The installer created a small certificate authority of its own and signed the registry's certificate with it. Add that CA to the server VM's trust store, as you did for Edge Manager's CA, then log in:

sudo install -m 0644 /opt/quay/quay-rootCA/rootCA.pem /etc/pki/ca-trust/source/anchors/lab-registry-ca.crt
sudo update-ca-trust
curl -I https://rhem.lab.internal:8443/health/instance
sudo podman login --authfile /root/.config/containers/auth.json -u admin -p edgelab123 rhem.lab.internal:8443

HTTP/2 200
...output omitted...
Login Succeeded!
  • The login is for root's podman (sudo), because the device image is built and pushed as root in the next module.
  • --authfile /root/.config/containers/auth.json adds the login to the file that already holds your Red Hat registry login. Without it, podman login writes under /run, and the login is lost when the server restarts.

Note

Two CAs now. Edge Manager's CA says "this is the real management server" and signs device identities. The registry's CA says "this is the real registry". Every device image you build has to carry both, or the device will refuse to talk to one of them. Keep them in mind as two separate things to protect and to distribute.
