Guided exercise 1 network-create

Create the lab network

Work from ~/edgelab, the folder you prepared in Prerequisites. Give the lab its own network, so the server and devices find each other by name and nothing depends on, or leaks into, your home LAN.

Outcomes

  • An SSH key made for this lab only.
  • A libvirt network rhem-lab (192.168.160.0/24) with DHCP, DNS for lab.internal, and NAT to the internet.

Before you begin

On the workstation, in ~/edgelab, confirm that the earlier exercises are complete:

./lab start network-create

Instructions

Make an SSH key for the lab

ssh-keygen -q -t ed25519 -N '' -C edgelab -f keys/id_ed25519
cat ssh_config
  • The key is only for lab VMs. You never put your personal key into images that devices boot from.
  • ssh_config names the lab VMs, their addresses, the login user and this key. That is why logging in is always ssh -F ~/edgelab/ssh_config NAME, and why nothing is added to your own SSH configuration.

Read the network definition

cat network.xml

The parts that matter later:

ElementWhat it doesEffect on the lab
<forward mode='nat'/>VMs reach the internet through the workstation; nothing outside can reach them.The server can pull from Red Hat's registry and CDN. Your LAN never sees the lab.
<domain name='lab.internal' localOnly='yes'/>libvirt's DNS answers for this domain itself and never forwards it upstream.Devices find the server as rhem.lab.internal. That name is baked into certificates and device images in later modules.
<host mac=… name=… ip=…/>A fixed DHCP lease, and a DNS record for the name.Each VM always gets the same address, so the guide's addresses stay true.

Note

Why DNS and not IP addresses? An agent is told where its server is by name, inside the device image. If devices used an IP address, moving the server would mean rebuilding every device. With a name, you only change what the name points to.

Create and start the network

virsh -c qemu:///system net-define network.xml
virsh -c qemu:///system net-start rhem-lab
virsh -c qemu:///system net-list --all
ip -br addr show virbr-rhem

 Name       State    Autostart   Persistent
---------------------------------------------
 default    active   yes         yes
 rhem-lab   active   no          yes

virbr-rhem       DOWN           192.168.160.1/24
  • -c qemu:///system selects the system-wide libvirt, where VMs can share a real network. Without it, virsh talks to your personal libvirt, which cannot. Every virsh command in this lab includes it.
  • net-define stores the definition; net-start creates the bridge virbr-rhem and starts a dnsmasq process for DHCP and DNS on it.
  • The bridge shows DOWN until the first VM is attached. That is normal.
  • Autostart is off on purpose: after a workstation reboot, run virsh -c qemu:///system net-start rhem-lab before starting the VMs.

Evaluation

On the workstation, in ~/edgelab, grade your work. Every line should end in SUCCESS; a FAIL line is followed by what to do about it.

./lab grade network-create

You can also look yourself:

virsh -c qemu:///system net-dumpxml rhem-lab

The output is the network as libvirt stored it. You should see the domain lab.internal and four host entries: rhem, edge-1, edge-2, edge-3.

Finish

./lab finish network-create

This confirms that the exercise is complete and names the next one. Nothing is cleaned up, because the later exercises build on what you made here.
