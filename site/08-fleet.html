Guided exercise 8 fleet-create

Manage devices as a fleet

Stop thinking about individual devices. A fleet is one description of what a kind of device should run, applied to every device whose labels match.

Outcomes

  • A fleet lab that selects all devices labelled site=lab.
  • All three devices owned by the fleet, with their OS image pinned by it.

Before you begin

On the workstation, in ~/edgelab, confirm that the earlier exercises are complete:

./lab start fleet-create

Instructions

Write the fleet

This is the first YAML file you write for Edge Manager. Paste the block, or create it with vi ~/fleet/lab-fleet.yaml; if you enter it by hand, use spaces only, two per level (the rules, and how to check your file).

mkdir ~/fleet
cat > ~/fleet/lab-fleet.yaml <<'EOF'
apiVersion: flightctl.io/v1beta1
kind: Fleet
metadata:
  name: lab
spec:
  selector:
    matchLabels:
      site: lab
  template:
    spec:
      os:
        image: rhem.lab.internal:8443/admin/edge-os:v1
EOF
PartMeaning
selector.matchLabelsWhich devices belong: every device carrying the label site=lab. You set that label when you approved the devices.
template.specWhat each of those devices should look like. This is the same structure as a single device's spec.
os.imageThe OS image the devices must run. They already run v1, so nothing will change on them yet; the fleet now owns that decision.

Note

Keep this file. It is the source of truth for your devices. In a real deployment it lives in git, and every change to the edge is a reviewed change to a file like this one. Edge Manager can also read fleets straight from a git repository.

Apply it

flightctl apply -f ~/fleet/lab-fleet.yaml
flightctl get fleets
flightctl get devices

The OWNER column changes to Fleet/lab within a few seconds. Nobody listed the devices: the label did it.

See what the fleet did to a device

flightctl get devices -l alias=edge-1 -o yaml | less

-l alias=edge-1 selects the device by its label, so you do not need its long name. In less, enter /owner to jump to the part shown here; q quits.

    labels:
      alias: edge-1
      site: lab
      …
    name: 1jn34ajbcdc1vhliuj5s7suq3ja49g5vjdqu101am2b9jgsrtd20
    owner: Fleet/lab
  spec:
    os:
      image: rhem.lab.internal:8443/admin/edge-os:v1
  status:

The device's spec is now a copy of the fleet's template, and owner records where it came from. The chain is:

 fleet template  ──(server copies it to every matching device)──▶  device spec
 device spec     ──(agent fetches it on its next check-in)──────▶  device makes itself match
 device status   ◀─(agent reports what is actually running)──────  device

Note

Why this matters at the edge. The server never pushes anything. It only records what each device should be. A device that is offline for a week simply fetches the current spec when it comes back, and skips everything in between. That is what makes fleets work over unreliable links.

Understand what "declarative" means here

Three rules to keep in mind before you start changing things. All three were observed on RHEM 1.4.0 while writing this guide:

RuleWhat happens
The template is the whole truth.Whatever the template does not list is removed from the devices. A fleet with no applications section uninstalls every application Edge Manager had deployed.
Membership follows labels.A new device approved with site=lab joins the fleet and receives the template without anyone touching the fleet.
Deleting a fleet does not wipe devices.The devices keep their last spec and keep running it; they just have no owner any more.

Evaluation

On the workstation, in ~/edgelab, grade your work. Every line should end in SUCCESS; a FAIL line is followed by what to do about it.

./lab grade fleet-create

You can also look yourself:

flightctl get devices

All three devices show Fleet/lab in the OWNER column.

Finish

./lab finish fleet-create

This confirms that the exercise is complete and names the next one. Nothing is cleaned up, because the later exercises build on what you made here.
