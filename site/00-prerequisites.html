Guided exercise 0 prep-workstation

Prepare the workstation

Get the workstation ready, download three things from Red Hat, and set up the folder you will work in.

Outcomes

  • A workstation that can run KVM virtual machines as your user.
  • A working folder ~/edgelab holding the lab files and your three inputs under fixed names.

Before you begin

RequirementDetail
Workstationx86_64 Linux with KVM (/dev/kvm exists). Written and tested on Fedora. On RHEL 9.8 and RHEL 10.2 the workstation steps were tested as far as creating the server VM.
Free capacityA machine with 16 GB of memory is enough: the four VMs are given 10.5 GiB between them (6 GiB for the server, 1.5 GiB for each of three devices). They need 50 GB of free disk space, and 4 or more CPU threads.
Red Hat accountWith a subscription that includes Red Hat Edge Manager. Module 3 shows how to check: the server must be offered an edge-manager repository.
Internet accessFrom the workstation, to registry.redhat.io, cdn.redhat.com, subscription.rhsm.redhat.com and mirror.openshift.com.

Instructions

Prepare the workstation

Install the virtualization tools and let your user manage system VMs:

sudo dnf install -y libvirt qemu-kvm qemu-img virt-install git make openssl
sudo systemctl enable --now libvirtd
sudo usermod -aG libvirt "$USER"

Every package is in the standard RHEL repositories: this list was checked against RHEL 9.8 and RHEL 10.2 (BaseOS and AppStream), and it is the same on Fedora. In the last command, "$USER" is your own login name; the shell fills it in, so type the command exactly as shown.

Log out and back in so the group membership applies, then check:

virsh -c qemu:///system list --all
virt-install --version
ls -l /dev/kvm

The first command must print a table (possibly empty) without asking for a password.

Note

Why the system libvirt? libvirt has two modes. Your personal one (qemu:///session) needs no privileges but cannot give VMs a shared network of their own. The system one (qemu:///system) can, and the lab needs that: devices have to reach the server by name. Membership of the libvirt group is what lets you use it without sudo.

Create the working folder

One folder holds everything the lab puts on the workstation. Deleting it at the end removes the lab's files.

mkdir ~/edgelab
cd ~/edgelab
git clone https://github.com/aclater/rhem-lab.git guide
cp guide/files/* .
ln -s guide/lab lab
mkdir images keys inputs
chmod 700 keys
chattr +C images
chmod o+x ~
ls

guide  images  inputs  keys  lab  network-disconnected.xml  network.xml  ssh_config
In ~/edgelabWhat it is
guide/This guide's repository. make -C guide serve starts a small web server for the guide in the background and prints its address: http://127.0.0.1:8765/, or the next free port if 8765 is taken. make -C guide stop stops it.
network.xml, ssh_configTwo small lab files copied out of the repository: the network definition, and SSH settings for the VMs. You read each one before using it.
labA link to the guide's lab command, which checks your work: ./lab start, ./lab grade and ./lab finish for each exercise, and ./lab status at any time. It only reads.
inputs/The three files you download next.
images/VM disks. Kept out of the git clone on purpose.
keys/An SSH key made for this lab only (module 1).

chattr +C turns off copy-on-write for new files in images. On btrfs, VM disks with copy-on-write fragment badly and get slow. On other filesystems the command may print an error you can ignore.

chmod o+x ~ lets the system's VM service, which runs as the user qemu, pass through your home folder to reach the disks in images. It allows passing through only: other users still cannot list or read your files. On RHEL a home folder is closed to other users, and without this virt-install fails with "Cannot access storage file".

Download the three inputs

Save each file under exactly the name shown. The rest of the guide refers to these names. The image keeps the file name Red Hat gives it.

Save asWhat it isWhere to get it
~/edgelab/inputs/rhel-9.8-x86_64-kvm.qcow2The RHEL 9.8 KVM guest image, about 1.4 GB. The server VM's disk starts as a copy of it.access.redhat.com/downloads/content/rhel: choose version 9.8, then "Red Hat Enterprise Linux 9.8 KVM Guest Image".
~/edgelab/inputs/rhsm-activationA two-line text file you write yourself:
org=1234567
key=my-activation-key		console.redhat.com → Activation keys: create a key (or reuse one). The page shows your organization ID.
~/edgelab/inputs/pull-secret.jsonYour Red Hat pull secret: a JSON file with a login for registry.redhat.io.console.redhat.com → Pull secret: "Download pull secret".

If you already keep any of these somewhere else, link instead of copying, for example ln -s /path/to/your/pull-secret.json inputs/pull-secret.json.

Protect the two secrets and check all three:

chmod 600 inputs/rhsm-activation inputs/pull-secret.json
ls -lL inputs
qemu-img info inputs/rhel-9.8-x86_64-kvm.qcow2

image: inputs/rhel-9.8-x86_64-kvm.qcow2
file format: qcow2
virtual size: 10 GiB (10737418240 bytes)
...output omitted...

The image must be reported as qcow2. The grading at the end of this module checks the content of the other two files for you.

Note

Why these three? The guest image saves you an operating system install. The activation key registers machines without anyone's password, which is also how you would register hundreds of servers or a build pipeline. The pull secret lets the server download Edge Manager's containers. Neither secret is ever copied into the repository or printed by a command in this guide.

Note

The download pages and their wording are as found at the time of writing and may move. Two more things are downloaded later, from inside the server VM, when they are needed: the Edge Manager packages (module 3) and Red Hat's mirror registry (module 5).

Evaluation

On the workstation, in ~/edgelab, grade your work. Every line should end in SUCCESS; a FAIL line is followed by what to do about it.

./lab grade prep-workstation

You can also look yourself:

ls -L inputs

pull-secret.json  rhel-9.8-x86_64-kvm.qcow2  rhsm-activation

From here on, every workstation command assumes your terminal is in ~/edgelab.

Finish

./lab finish prep-workstation

This confirms that the exercise is complete and names the next one. Nothing is cleaned up, because the later exercises build on what you made here.
