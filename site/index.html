Deploy Red Hat Edge Manager

You build a small edge estate on one workstation: an Edge Manager server, three edge devices, and workloads rolled out to them as a fleet. You type every command; each step says what it does, why, and what it changes in the end result.

Outcomes

  • rhem: a RHEL 9 VM running Red Hat Edge Manager 1.4 as podman containers under systemd (quadlets), plus the registry that holds your device and application images.
  • edge-1, edge-2, edge-3: RHEL image mode (bootc) VMs. They boot from an image you built, enroll with the server, and from then on change only when the server tells them to.
  • A fleet that decides which OS image and which applications those devices run, and an update rolled out through it.

How the pieces fit

PieceWhat it isWhy it matters here
Red Hat Edge Manager (RHEM)The management service. Upstream project: Flight Control, which is why the commands and packages are called flightctl.Holds the desired state of every device and collects their status.
Agentflightctl-agent, a small service on each device.Devices always call the server, never the other way round. A device behind NAT or on a poor link still works, and catches up after being offline.
Image mode (bootc)The device's whole operating system is a container image, booted directly.An OS update is "switch to this image and reboot", with the old image kept for rollback. Nothing is patched in place.
FleetA template plus a label selector.You describe one device spec; every device whose labels match gets it. Changing the template rolls out to all of them.
RegistryWhere OS and application images live.Devices pull from it, so it has to be reachable from the edge. Here it sits next to the server.

Before you start

Prerequisites lists what the workstation needs, the three files to download from Red Hat, and how to set up the working folder ~/edgelab. The guide always uses real paths relative to that folder, so what you read is what you type.

Note

Working style. Keep two terminals open: one on the workstation, one logged in to the rhem VM. Every command block is labelled with where it runs; workstation commands assume you are in ~/edgelab. Tick the box on each step as you finish it; the sidebar keeps count.

The lab command

Each module is an exercise with a name, and the lab command checks your work on it. Run it on the workstation, in ~/edgelab. It only reads; it never changes anything.

Entering commands by hand

Every block has a Copy button, but entering commands by hand is how they stick. The guide is written so that you can do either. Two kinds of block need care when entered by hand: files written with cat > file <<EOF, and anything in YAML.

Entering a file in the shell

Enter the first line, cat > some-file <<'EOF', and press Enter. The shell shows a > prompt and waits. Enter the file's lines, then EOF on a line of its own, at the very start of the line. You cannot go back to an earlier line, so for anything longer than a few lines use an editor instead: vi some-file gives the same result.

YAML rules used in this guide

RuleDetail
Spaces, never tabsA tab anywhere in the indentation is an error. Edge Manager rejects the file with found character that cannot start any token.
Two spaces per levelEach level of nesting is indented two more spaces than its parent. YAML accepts any consistent number; this guide always uses two.
Same level, same columnKeys that belong together start in exactly the same column. Indentation is the structure: one space out of place moves a setting to a different parent, or makes the file invalid.
ListsEach item starts with a dash and one space. In this guide the dash sits two spaces in from the key above it, and the item's other fields line up under the first one, after the dash.
Colon, then a spacename: lab, not name:lab.
Quote values that contain a colon"8080:8080".
spec:                    # column 0
  selector:              # 2 spaces
    matchLabels:         # 4
      site: lab          # 6
  template:              # 2: same level as selector
    spec:                # 4
      applications:      # 6
        - name: hello    # 8: dash, space, first field of the item
          ports:         # 10: lines up under "name"
            - "8080:8080"

Make the editor help

The lab VMs have vi. This setting makes the Tab key insert two spaces and keeps the indentation of the previous line. Enter it inside vi before you start, or put the line without the leading colon in ~/.vimrc to make it permanent:

:set expandtab shiftwidth=2 softtabstop=2 autoindent

Check what you entered

Before applying a YAML file, check it. The first command finds tabs and prints nothing if there are none. The second parses the file and fails with the line number of the first mistake; it works on the server VM, where Edge Manager installs the YAML library it needs:

grep -nP '\t' lab-fleet.yaml
python3 -c "import yaml,sys; yaml.safe_load(open(sys.argv[1])); print('valid YAML')" lab-fleet.yaml

Valid YAML can still say the wrong thing, for example a key indented under the wrong parent. After applying, flightctl get fleet/lab -o yaml shows the fleet as Edge Manager stored it; compare its shape with the guide. A setting that is missing there was indented in the wrong place.
