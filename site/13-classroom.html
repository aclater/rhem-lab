Appendix B classroom

Deliver the lab in a classroom

For instructors. Prepare the lab once on a connected machine, then give it to students whose workstations have no internet access and no Red Hat account. Each student still builds everything by hand.

Outcomes

  • A classroom kit: one folder, 6.5 GB, that holds the guide, the RHEL guest image and everything the lab would otherwise download.
  • Student workstations set up from the kit with one command, ready to start the lab with no network at all.

How a class differs from working alone

Working aloneIn a class
Each reader has a Red Hat account, an activation key and a pull secret.Only the instructor does, and only while building the kit. The kit holds no account details, and student servers are never registered.
The workstation downloads the guide, the guest image, packages and images.Everything comes from the kit. Nothing is downloaded during the class.
The reader starts at Prepare the workstation.Students start at Run the lab disconnected, part 2. The kit replaces part 1 and the downloads of module 0.

Each student's lab runs inside their own workstation, on a private network that exists only there. Workstations do not need to reach each other, the instructor or anything else during the class.

Important

The kit contains Red Hat software obtained with the instructor's subscription. Confirm that your subscription terms cover the students' use before you hand it out. This guide does not cover licensing.

Before you begin

WhoNeeds
Instructor's workstationEverything in Prepare the workstation, completed, with internet access; the ansible-core package; 15 GB of free disk space on top of the lab's own.
Each student workstationx86_64 RHEL 9, RHEL 10 or Fedora with KVM, 16 GB of memory, 4 or more CPU threads and 60 GB of free disk space. The packages below, installed in advance, and the student's user in the libvirt group.

Install the packages on each student workstation while it still has a package source:

sudo dnf install -y libvirt qemu-kvm qemu-img virt-install make openssl ansible-core
sudo systemctl enable --now libvirtd
sudo usermod -aG libvirt "$USER"

These are the packages of module 0 without git, plus ansible-core. All are in the standard RHEL repositories. The kit does not carry them, because they must match each workstation's own release.

Note

The lab network uses the addresses 192.168.160.0/24 inside each workstation. If the classroom's own network uses the same range, the workstations cannot be on both at once; disconnect them from the classroom network for the lab.

Instructions: build the kit, on the instructor's workstation

Gather the offline files

This is part 1 of Run the lab disconnected. Do it by hand as written there, or run the playbook, which takes 8 to 12 minutes:

ansible-playbook guide/ansible/disconnected-prepare.yml

In the kitWhat it is
guide/A copy of this guide, the lab command and the playbooks, without version history.
inputs/The RHEL 9.8 guest image. Your activation key and pull secret are not copied.
offline/The four offline files.
SHA256SUMSChecksums of the files in inputs and offline, so that each workstation can check its copy.
README.txtThe student's instructions: the same commands as in the next section.

Rebuild the kit when the guide changes: the playbook copies the guide again and reuses the large files that are already there.

Get the kit to the students

Use whichever suits the room. The kit works from any folder.

Portable media. Copy the folder classroom-kit to a drive with 7 GB free and a file system that holds files larger than 4 GB (exFAT or XFS, not FAT32). Students can run the setup straight from the drive.

Over the classroom network. Pack the kit into one file and serve it from your workstation:

tar -cf classroom-kit.tar classroom-kit
python3 -m http.server 8000

Students fetch and unpack it. The address is your workstation's address on the classroom network, which you give them:

curl -O http://<instructor_address>:8000/classroom-kit.tar
tar -xf classroom-kit.tar

Stop the server with Ctrl+C when everyone has the file. Your workstation's firewall must allow port 8000 for this: sudo firewall-cmd --add-port=8000/tcp opens it until the next reboot.

Instructions: on each student workstation

Set up the workstation from the kit

The student opens a terminal in the kit folder, wherever it is, and runs:

ansible-playbook guide/ansible/classroom-student.yml

...output omitted...
TASK [What to do next] *********************************************************
ok: [localhost] => {
    "msg": "The working folder /home/student/edgelab is ready. Go there, start the guide with \"make -C guide serve\", and begin at \"Run the lab disconnected\", part 2."
}
...output omitted...

The playbook does this:

  • Checks the workstation: KVM, the right to manage VMs, the lab's tools, 60 GB of free space.
  • Checks every large file in the kit against its checksum.
  • Creates ~/edgelab exactly as module 0 does: the guide, the lab files, the lab command, the folders, the guest image and the four offline files.
  • Lets the VM service pass through the student's home folder to reach the disk images (chmod o+x ~). This is its only change outside ~/edgelab.

A failed check stops the playbook and says what is missing. It can be run again.

Start the lab

cd ~/edgelab
./lab grade prep-workstation
make -C guide serve

The last command prints the address of the guide, served from the student's own workstation. Students begin at Run the lab disconnected, part 2, "Create the disconnected network", and follow it through the modules.

Running the class

QuestionAnswer
How long does it take?The module times on the overview page add up to about three hours. Offline, nothing waits on a download.
Where is a student?./lab status on their workstation lists every exercise as passed or not and names the next step. ./lab grade exercise explains each failure.
Can I shorten the server setup?Yes. ansible-playbook guide/ansible/disconnected-server.yml, run in ~/edgelab, builds the disconnected network and a server ready for Edge Manager in 3 to 6 minutes. Students then continue from "Configure and start Edge Manager" in Appendix A. Use it when the class is about managing devices more than about installing offline, or to rescue a student who has fallen behind.
How do I reset a workstation for the next class?The student follows Remove the lab, skipping the unregistration step. The kit is untouched and can be used again.
