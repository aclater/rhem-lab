Appendix A disconnected

Run the lab disconnected

Do the whole lab on a network with no route to the internet. You gather everything on a connected machine first, carry it across, and then install and run from local content only.

Outcomes

  • A set of four files that holds everything the lab would otherwise download.
  • The Edge Manager server, the registry, the device image and three devices, built and running with no internet access.

What changes when you are disconnected

The connected lab gets this from the internetDisconnected, it comes from
Edge Manager packages, and podman and its dependencies, from Red Hat's CDN after registering the serverThe RPMs in Red Hat's offline bundle. The server is never registered.
Edge Manager's container images from registry.redhat.ioThe same images in the offline bundle, served by a small local registry on the server, with their signatures.
The mirror registry installerThe same archive, downloaded in advance.
The RHEL image mode base image, the disk image builder and the application's base imageOne archive of the three images, saved in advance and loaded on the server.
The agent package inside the device image buildThe agent RPM in the offline bundle, offered to the build as a local repository.

Everything after the server is installed (logging in, enrolling devices, fleets, workloads, updates) is identical. The two parts below replace modules 1, 3 and the download steps of modules 5 and 6.

Before you begin

Complete Prepare the workstation while the workstation is still connected. Part 1 also needs the internet. From part 2 on, nothing does.

Instructions: part 1, prepare while connected

Create a prep VM on a connected network

Red Hat's bundling tool has to run on registered RHEL of the same major version as the server, so the preparation happens in a temporary RHEL 9 VM. Create the connected lab network and the VM:

ssh-keygen -q -t ed25519 -N '' -C edgelab -f keys/id_ed25519
virsh -c qemu:///system net-define network.xml
virsh -c qemu:///system net-start rhem-lab
cp --sparse=always inputs/rhel-9.8-x86_64-kvm.qcow2 images/prep.qcow2
qemu-img resize images/prep.qcow2 60G

virt-install --connect qemu:///system --name prep --memory 4096 --vcpus 2 \
  --import --disk images/prep.qcow2 --osinfo rhel9-unknown \
  --network network=rhem-lab,mac=52:54:00:a0:00:11 \
  --cloud-init clouduser-ssh-key=keys/id_ed25519.pub \
  --boot uefi --graphics none --noautoconsole

Skip the ssh-keygen line if you already made the lab key. After about 30 seconds, log in:

ssh -F ~/edgelab/ssh_config prep

Register the prep VM and install the tools

In the prep VM, register with your organization ID and activation key, as in Install Red Hat Edge Manager, then enable the Edge Manager repository and install the tools:

sudo subscription-manager register --org <organization_id> --activationkey <activation_key>

sudo subscription-manager repos --enable edge-manager-1.4-for-rhel-9-x86_64-rpms
sudo dnf install -y flightctl-cli skopeo createrepo_c podman

Give root's podman your Red Hat registry login. On the workstation:

scp -F ~/edgelab/ssh_config inputs/pull-secret.json prep:pull-secret.json

sudo install -D -m 0600 pull-secret.json /root/.config/containers/auth.json
rm pull-secret.json

Build the offline bundle

sudo flightctl-mirror-images --variant rhem-el9 --bundle /home/cloud-user/rhem-bundle.tar.gz --bundle-rpms --rpm-createrepo --tag-override 1.4.0
sudo chown cloud-user: rhem-bundle.tar.gz
ls -lh rhem-bundle.tar.gz

[INFO]    Images: 22
[INFO]  Bundle created: /home/cloud-user/rhem-bundle.tar.gz
-rw-r--r--. 1 cloud-user cloud-user 1.8G … rhem-bundle.tar.gz

About four minutes. The options:

OptionMeaning
--variant rhem-el9Red Hat's images, for a RHEL 9 server.
--bundleWrite one archive holding the container images, with two scripts to unpack them on the other side.
--bundle-rpms --rpm-createrepoAlso include the Edge Manager server, CLI and agent RPMs with everything they depend on (224 packages, podman included), as a ready-made repository.
--tag-override 1.4.0Pin the images and the RPMs to one release, so they match each other.

Note

Red Hat's documentation calls this tool mirror-images. The command installed by the flightctl-cli package is flightctl-mirror-images.

Fetch the gateway image

The 1.4.0 bundle leaves out one image that the server needs: the nginx image behind the gateway service. Fetch it separately, with its signatures:

mkdir gateway-image
sudo skopeo copy docker://registry.redhat.io/rhel9/nginx-124:1-1792441608 dir:/home/cloud-user/gateway-image
sudo chown -R cloud-user: gateway-image
tar -cf gateway-image.tar gateway-image

The exact tag belongs to this Edge Manager release. On an installed server it is the Image= line of /usr/share/containers/systemd/flightctl-gateway.container.

Fetch what the rest of the lab downloads

The mirror registry installer:

curl -LO https://mirror.openshift.com/pub/openshift-v4/x86_64/clients/mirror-registry/1.3.11/mirror-registry.tar.gz

The three images the lab builds from, saved into one archive:

sudo podman pull registry.redhat.io/rhel9/rhel-bootc:9.8
sudo podman pull registry.redhat.io/rhel9/bootc-image-builder:latest
sudo podman pull registry.access.redhat.com/ubi9/nginx-124:latest
sudo podman save -m -o lab-images.tar registry.redhat.io/rhel9/rhel-bootc:9.8 registry.redhat.io/rhel9/bootc-image-builder:latest registry.access.redhat.com/ubi9/nginx-124:latest
sudo chown cloud-user: lab-images.tar
ls -lh *.tar *.tar.gz

-rw-r--r--. 1 cloud-user cloud-user 111M … gateway-image.tar
-rw-r--r--. 1 cloud-user cloud-user 2.7G … lab-images.tar

Carry the files to the workstation and remove the prep VM

mkdir offline
scp -F ~/edgelab/ssh_config prep:rhem-bundle.tar.gz prep:gateway-image.tar prep:mirror-registry.tar.gz prep:lab-images.tar offline/
ls -lh offline

These four files, 5.3 GB together, are what you would put on portable media. Release the prep VM's registration, then delete the VM and the connected network:

sudo subscription-manager unregister

virsh -c qemu:///system destroy prep
virsh -c qemu:///system undefine prep --nvram
virsh -c qemu:///system net-destroy rhem-lab
virsh -c qemu:///system net-undefine rhem-lab
rm images/prep.qcow2

Instructions: part 2, the lab with no internet

The exercises keep their names, and the lab command checks them as in the connected lab. Run ./lab grade network-create after the first step below, ./lab grade server-create after the second, and ./lab grade rhem-install once Edge Manager is started.

Create the disconnected network

If you did not do part 1 on this workstation, for example because you received the offline files from someone else, make the lab's SSH key first. If the command asks whether to overwrite an existing key, answer n: you already have it.

ssh-keygen -q -t ed25519 -N '' -C edgelab -f keys/id_ed25519

Then create the network. This step replaces Create the lab network:

cp guide/files/network-disconnected.xml .
cat network-disconnected.xml
virsh -c qemu:///system net-define network-disconnected.xml
virsh -c qemu:///system net-start rhem-lab

It is the lab network without the line <forward mode='nat'/>: same name, same addresses, same DNS, and no way out. One addition matters: it still hands out a default route.

Important

Edge Manager's first start looks up the server's own address by asking the system which route it would use to reach the internet. On a network with no default route that lookup fails, no certificates are created, and no service starts. The route here leads nowhere, which is enough.

Start a local registry and import the images

Edge Manager's services pull their images when they start. Offline, those pulls are answered by a small registry on the server itself, which is included in the bundle:

sudo skopeo copy "dir:/home/cloud-user/rhem-bundle/images/library/registry:2" containers-storage:docker.io/library/registry:2
mkdir ~/registry-data
sudo podman run -d --name local-registry --network=host --security-opt label=disable -v /home/cloud-user/registry-data:/var/lib/registry --restart=always docker.io/library/registry:2
sudo systemctl enable podman-restart.service
curl http://localhost:5000/v2/

{}

Import the bundled images, and the gateway image you fetched separately:

sudo ./import.sh
cd ~
tar -xf gateway-image.tar
sudo skopeo copy --dest-tls-verify=false dir:/home/cloud-user/gateway-image docker://localhost:5000/rhel9/nginx-124:1-1792441608
curl http://localhost:5000/v2/_catalog

Important

Run the registry and the import with sudo. A registry started as your own user stops when you log out. An import run as your own user stores the image signatures in your home folder, where the system's podman does not look.

Point podman at the local registry

Add these four blocks at the end of the registries configuration, so that a pull from any of the public registries is answered by the local one:

sudo vi /etc/containers/registries.conf

[[registry]]
prefix = "registry.redhat.io"
location = "localhost:5000"
insecure = true

[[registry]]
prefix = "registry.access.redhat.com"
location = "localhost:5000"
insecure = true

[[registry]]
prefix = "quay.io"
location = "localhost:5000"
insecure = true

[[registry]]
prefix = "docker.io"
location = "localhost:5000"
insecure = true

RHEL only accepts Red Hat's images when their signatures check out, and by default it fetches the signatures from the internet. The import stored them on the server. Edit two files so that the lookup is local. In each, replace the address after sigstore: so that the line reads as shown, keeping its indentation:

sudo vi /etc/containers/registries.d/registry.redhat.io.yaml
sudo vi /etc/containers/registries.d/registry.access.redhat.com.yaml

         sigstore: file:///var/lib/containers/sigstore

Test a pull. It is answered locally and its signature is verified:

sudo podman pull registry.redhat.io/rhel9/postgresql-16:9.7-1766414426

Note

Without the signature change, every pull fails with "A signature was required, but no signature exists". Signature checking stays on; only the place it reads from changes.

Configure and start Edge Manager

Continue with Install Red Hat Edge Manager from step 5, "Tell Edge Manager its name", to the end. The first start is quicker than when connected, because the images come from the same machine.

Then do Log in for the first time as written.

Install the registry from the carried archive

In Install a registry, replace step 1 (the download and its checksum) with:

mkdir ~/mirror-registry
cd ~/mirror-registry
tar xzf ~/mirror-registry.tar.gz

The rest of that module is unchanged: the installer carries its own images.

Build the device image from local content

Before you start Build the device image, load the three images you saved:

sudo podman load -i ~/lab-images.tar

Loaded image: registry.redhat.io/rhel9/rhel-bootc:9.8
Loaded image: registry.redhat.io/rhel9/bootc-image-builder:latest
Loaded image: registry.access.redhat.com/ubi9/nginx-124:latest

Then follow Build the device image with three differences.

The Containerfile. The agent is installed from the bundle's RPMs, not from Red Hat's CDN. In step 3, "Write the Containerfile", this replaces the first RUN instruction and the comment above it, the one that enables the Edge Manager repository and installs flightctl-agent:

# The Edge Manager agent, from the RPMs in the offline bundle (mounted at /rpms during the build).
RUN dnf -y install --nogpgcheck --disablerepo="*" --repofrompath=bundle,/rpms --enablerepo=bundle flightctl-agent && \
    dnf -y clean all && \
    systemctl enable flightctl-agent.service

The build. In step 4, "Build and push the OS image", offer the bundle's RPM folder to the build with -v. The push is unchanged:

cd ~/device
sudo podman build -v /home/cloud-user/rhem-bundle/rpms:/rpms:ro,z -t rhem.lab.internal:8443/admin/edge-os:v1 .

The disk image. In step 5, "Turn the image into a disk", in the bootc-image-builder command, use --pull=never in place of --pull=newer, so that it uses the builder image you loaded.

Use the same -v option when you rebuild the image as v2 in Update and roll back the operating system.

Do the rest of the lab

Create and enroll edge devices, Manage devices as a fleet, Deploy a workload and Update and roll back the operating system need no changes. Devices only ever talk to the server and the lab registry.

In Remove the lab, skip the first step: the server was never registered.

Evaluation

The lab command works as in the connected lab. It recognises a disconnected install by the folder ~/edgelab/offline, and does not expect the server to be registered.

./lab status

Timings seen with no internet access: packages installed from the bundle in under a minute, images imported in 20 seconds, the device image built in 45 seconds and its disk in a little over two minutes, the application on all three devices two minutes after the fleet change, and an operating system update on all three in a little over three minutes.
