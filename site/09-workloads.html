Guided exercise 9 workload-deploy

Deploy a workload

Package an application as a container image, add it to the fleet, and watch all three devices start running it. Then ship a new version the same way.

Outcomes

  • A small web application, hello, in your registry as versions v1 and v2.
  • All three devices serving it on port 8080, deployed and updated only by editing the fleet.

Before you begin

On the workstation, in ~/edgelab, confirm that the earlier exercises are complete:

./lab start workload-deploy

Instructions

Build the application image

mkdir -p ~/apps/hello
cd ~/apps/hello
cat > Containerfile <<'EOF'
FROM registry.access.redhat.com/ubi9/nginx-124:latest
ARG APP_VERSION=dev
USER 0
RUN printf "<h1>Hello from the edge</h1>\n<p>Version: %s</p>\n" "${APP_VERSION}" > /opt/app-root/src/index.html && \
    chown 1001:0 /opt/app-root/src/index.html
USER 1001
EXPOSE 8080
CMD ["nginx", "-g", "daemon off;"]
EOF
sudo podman build --build-arg APP_VERSION=v1 -t rhem.lab.internal:8443/admin/hello:v1 .
sudo podman push rhem.lab.internal:8443/admin/hello:v1
  • The base is Red Hat's UBI 9 nginx image, which is free to use and redistribute and needs no login.
  • The page shows its own version, so you can see which one a device is serving.
  • The image runs as a non-root user and listens on 8080. Both matter in the next step.

Add the application to the fleet

Add an applications section to the template. The whole file again, so you can paste it:

cat > ~/fleet/lab-fleet.yaml <<'EOF'
apiVersion: flightctl.io/v1beta1
kind: Fleet
metadata:
  name: lab
spec:
  selector:
    matchLabels:
      site: lab
  template:
    spec:
      os:
        image: rhem.lab.internal:8443/admin/edge-os:v1
      applications:
        - name: hello
          appType: container
          image: rhem.lab.internal:8443/admin/hello:v1
          runAs: flightctl
          ports:
            - "8080:8080"
EOF
flightctl apply -f ~/fleet/lab-fleet.yaml
FieldMeaning
appType: containerRun one container image as a service. Other types are quadlet and compose for applications made of several containers, helm for devices that run MicroShift, and vm.
imageWhere the device pulls the application from: your registry.
runAs: flightctlRun the container as the unprivileged flightctl user on the device (rootless), not as root. The user exists because the agent package created it in your OS image.
portsPublish the container's port 8080 on the device's port 8080.

Watch the rollout

watch -n 5 flightctl get devices

Over about two minutes the devices go through these states (leave watch with Ctrl+C):

UPDATEDAPPLICATIONSWhat the device is doing
UpdatingNoApplicationsIt has fetched the new spec and is downloading the application image.
UpToDateDegradedThe spec is applied; the application is installed but not yet reporting as running.
UpToDateHealthyThe container is running.

Note

Degraded for a short while after a change is normal: it means "not all applications are running yet". It is a problem only if it stays.

From the workstation, ask each device for the page:

curl http://192.168.160.21:8080/
curl http://192.168.160.22:8080/
curl http://192.168.160.23:8080/

<h1>Hello from the edge</h1>
<p>Version: v1</p>

See how it runs on the device

Ask the server what the device reports:

flightctl get devices -l alias=edge-1 -o yaml | less

In less, enter /status: to jump to what the device reports, then find applications: just below it; q quits.

  status:
    applications:
    - appType: container
      …
      name: hello
      ready: 1/1
      restarts: 0
      runAs: flightctl
      status: Running
    applicationsSummary:
      info: Device's application workloads are healthy.

Now look on the device itself. Log in to it from the workstation:

ssh -F ~/edgelab/ssh_config edge-1

The application runs as the flightctl user, so become that user and look around:

sudo -u flightctl -i
podman ps
cat .config/containers/systemd/hello/*.container
exit

CONTAINER ID  IMAGE                                  COMMAND               CREATED        STATUS        PORTS                             NAMES
794191ca43ba  rhem.lab.internal:8443/admin/hello:v1  nginx -g daemon o...  2 minutes ago  Up 2 minutes  0.0.0.0:8080->8080/tcp, 8443/tcp  systemd-hello-flightctl-…-app

[Container]
Image=rhem.lab.internal:8443/admin/hello:v1
PublishPort=8080:8080

[Service]
Restart=on-failure
RestartSec=5

[Install]
WantedBy=default.target

Leave the device with exit.

Note

No magic. The agent turned your four lines of YAML into a quadlet in the flightctl user's home, and systemd runs it: the same mechanism that runs Edge Manager on the server. If the container crashes, systemd restarts it, with or without a connection to the server. The application keeps running through any outage of the management side.

Ship version 2

An application update is a new image tag and a one-line change to the fleet. Build and push version 2:

cd ~/apps/hello
sudo podman build --build-arg APP_VERSION=v2 -t rhem.lab.internal:8443/admin/hello:v2 .
sudo podman push rhem.lab.internal:8443/admin/hello:v2

Edit the fleet file and change the application's image tag from v1 to v2. It is the last image: line in the file; leave the os image line alone.

vi ~/fleet/lab-fleet.yaml

Confirm the change and apply it:

grep image: ~/fleet/lab-fleet.yaml
flightctl apply -f ~/fleet/lab-fleet.yaml

        image: rhem.lab.internal:8443/admin/edge-os:v1
          image: rhem.lab.internal:8443/admin/hello:v2
/home/cloud-user/fleet/lab-fleet.yaml: applying fleet/lab: 200 OK

Wait about two minutes, then ask the devices again:

curl -s http://192.168.160.21:8080/ | grep Version
curl -s http://192.168.160.22:8080/ | grep Version
curl -s http://192.168.160.23:8080/ | grep Version

<p>Version: v2</p>
<p>Version: v2</p>
<p>Version: v2</p>

All three devices changed at about the same time, because nothing in the fleet says otherwise. The next module controls that.

Note

Tags are a decision. The fleet names an exact version, v2, not latest. What runs at the edge changes only when the fleet file changes, and going back is the same edit in reverse.

Evaluation

On the workstation, in ~/edgelab, grade your work. Every line should end in SUCCESS; a FAIL line is followed by what to do about it.

./lab grade workload-deploy

You can also look yourself:

flightctl get devices

All three devices show UpToDate, and Healthy in both the applications and system columns.

Finish

./lab finish workload-deploy

This confirms that the exercise is complete and names the next one. Nothing is cleaned up, because the later exercises build on what you made here.
